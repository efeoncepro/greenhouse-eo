Emma decide cuándo hace falta una persona. El workflow decide quién recibe el ticket. Son dos responsabilidades separadas y verificables.

Workflow 1876744588

Resume, clasifica, limpia el owner técnico y ejecuta el routing humano.

1 · Resumir registroSintetiza el ticket y la conversación asociada.
2 · Enviar a la IADevuelve una categoría semántica controlada.
3 · Editar registroBorra a Emma como propietaria técnica.
4 · RamificaciónAbre cotización, seguimiento, Calidad/otros o contingencia.
EntradaActivación manual desde el Customer Agent.

Límite de responsabilidad
2 capas

Customer Agent para decidir el handoff; workflow para distribuir el ticket.

Qué no es este flujo

No es una acción externa de Emma ni un agente ejecutado dentro del workflow. La configuración de handoff selecciona este workflow de tickets como mecanismo de distribución.

Las fallas que requieren observación

Clasificación no reconocidaActiva la ruta de contención: María Paz y luego Marco.
Emma conserva el ownerLas acciones humanas pueden omitirse porque no sobrescriben.
Resumen agotadoLa acción declara un máximo de 3.000 ejecuciones mensuales.
Créditos insuficientesLa acción inteligente de clasificación puede fallar.
Chat terminadoNo es posible reabrir esa misma conversación.
Solicitud por nombre“Quiero hablar con Pablo” activa handoff; no garantiza owner nominal.
Clasificación semánticaLos marcadores “QA”, “PRUEBA” o “test” no alteran por sí solos la necesidad real.
Prioridad sustantivaSi hay varias intenciones, se elige la necesidad operativa principal.
