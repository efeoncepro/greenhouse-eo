# Plan de entrada por situación

- Cuenta/entidad/mercado/iniciativa y owner:
- Situación principal: proveedor actual / equipo saturado / proyecto puntual / transformación CRM / operación continua:
- Evidencia/fuente/fechas/ámbito; qué está declarado, observado o inferido:
- ICP y capacidad: owner/verdict/gaps; historia/restricciones vigentes:
- Relación por persona y con quién; demanda por iniciativa:
- Alternativa actual e inacción; por qué podría no necesitar Efeonce:
- Una tesis y pregunta prioritaria, ajustadas al hilo:
- Oferta candidata, owner y estado; límites de práctica/geografía/proveedor:

| Rol aplicable a esta decisión | Persona o brecha | Participación/autoridad: evidencia o hipótesis | Criterio/tensión | Ruta de validación |
| --- | --- | --- | --- | --- |
| Operador / problem owner | | | | |
| Sponsor / comprador / validadores que apliquen | | | | |
| Aceptación / implementación / contratación según fase | | | | |

- Objetivo y base de 2–3 adicionales pertinentes; brechas que requieren ampliar / límite de esfuerzo:
- Prueba mínima: destinatario, incertidumbre, criterio sugerido o confirmado, confirmación/refutación:
- Fuente/fecha/derechos de uso; real/simulado/propuesto; claims permitidos y límites:
- Esfuerzo/owner/acceso requerido; no confundir simulación con capacidad reservada:
- Siguiente acción / owner / fecha o condición; propuesta o acordada con comprador:
- Paradas o no-fit; qué evidencia permitiría revisar la decisión:
- Permisos existentes por acción y readback si hay operación autorizada:
- Handoff a Commercial/práctica/HubSpot; completar, conservar, pendiente y sistema si hay plan CRM:

Usar con [situation-entry-playbooks](../references/situation-entry-playbooks.md). No asignar precio, SLA,
rol comprador, etapa CRM o aprobación por elegir una situación; no registrar Contact/Lead sin email individual
corporativo verificado. Datos reales en expediente autorizado, nunca en este ejemplo versionado.
