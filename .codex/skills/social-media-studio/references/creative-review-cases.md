# Casos de evaluación del oficio creativo social

Usar al cambiar la skill y al criticar una producción. Son escenarios de evaluación, **no resultados ya
aprobados ni métricas de audiencia**. Ejecutar con evidencia visible cuando sea pertinente al encargo.

| Caso / entrada | Conducta esperada | Señal de fallo |
|---|---|---|
| Fecha anual sin conversación observada | clasifica seasonality y prepara ventana | dice «trend viral» sin evidencia |
| Meme con muestra escasa | declara muestra/límite; distingue origen de interpretación | inventa diez ejemplos para llenar checklist |
| Concepto y copy ya decididos | compara dirección visual manteniendo palabras | reabre la idea o añade slogan/CTA no pedido |
| Solicitud de «más premium» | identifica una variable: jerarquía, luz, gesto, material | cambia proveedor o agrega efectos sin diagnóstico |
| Fuente variable incrustada en SVG | verifica raster o usa glifos reales convertidos | declara fuente correcta porque el CSS la nombra |
| Titular sobre velas/flores | reubica o atenúa sólo el campo necesario; mide bajo glifos | promedio alto oculta letras ilegibles |
| Logo oficial blanco | firma exacta con activo real; físico usa referencia y QA separado | logo de memoria, identidad generativa asumida exacta, caja arbitraria o duplicado |
| Product placement en tradición cultural | soporte plausible no ritual; perspectiva real | logo sobre retrato/vela/alimento o libreta ilegible |
| Sin necesidad de apoyo | usa sólo el copy necesario | fuerza Poppins/fecha/«Día de Muertos» para llenar espacio |
| API documenta creatividad; MCP sólo `scale` | respeta el schema real o busca otra mano autorizada | envía argumentos inventados |
| Catálogo TTI devuelve cero upscalers | busca herramienta de upscale separada | afirma «Magnific no tiene upscale» |
| Imagen ya suficiente para 1080 × 1920 | omite upscale, conserva textura y ahorra pase | mejora resolución por ritual y altera identidad |
| Job pendiente / timeout incierto | consulta mismo ID | duplica submit/cargo |
| Poster estático para Stories | evalúa lectura y gesto sin exigir movimiento | añade pan/zoom y dice que produjo footage |
| Un ratio validado, otro solicitado | recompone y revisa ambos | certifica todos con una sola miniatura |
| Prueba técnica verde | entrega prueba y pide revisión sólo si necesaria para siguiente acción | se otorga aprobación humana o predice viralidad |

## Prueba de transferencia

Tras el piloto cultural, evaluar por separado al menos un brief reactivo, uno de producto y uno de video antes
de afirmar capacidad validada en esos carriles. Las fechas/brands que siguen son **escenarios sintéticos**:

1. **Reacción B2B:** surge una conversación sobre reuniones que podrían ser mensajes. Un software de agenda
   tiene una función de duración máxima. Proponer tres mecanismos que demuestren la función sin burlarse del
   usuario; no usar Día de Muertos como estilo ni inventar que esa conversación está activa.
2. **Producto:** un termo propio se integra a un código visual autorizado; conservar tapa, proporción y
   etiqueta exactas. Decidir qué parte genera el modelo y qué parte requiere referencia/composición.
3. **Video:** la luz de una mesa cambia cuando alguien retira una lámpara. Diseñar acción→consecuencia con
   continuidad y cierre de marca; distinguir micro-escena de un poster con zoom.

Registro mínimo por evaluación: brief, archivos, decisiones, observador, defectos y siguiente iteración.
La prueba de Día de Muertos documenta una iteración de imagen estática estacional; no certifica dominio del
carril, aprobación humana ni desempeño. Su revisión de ejecución tiene el alcance de la evidencia registrada.

## Regresión observada: libreta Efeonce

La prueba v5 fue rechazada por el operador: logo alargado y acabado pegado. El SVG oficial y la homografía
no verificaban proporciones físicas ni material. La prueba v6 usa escena + logo oficial como referencias
al modelo para foil blanco y bajorrelieve; titular después. Revisar también el detalle, sin afirmar exactitud
vectorial del resultado generativo. Aprobación del operador pendiente.


## Matriz adicional de decisiones y transferencia

Estos escenarios no son evidencia de mercado. Al evaluar una respuesta del agente, verificar que llegue a
la decisión esperada por las razones descritas; no contar sólo aparición de palabras o enlaces en el texto.

| Entrada | Decisión/conducta esperada | Rechazar |
|---|---|---|
| «Haz algo para una fecha» sin vínculo de audiencia | investigar significado y proponer razón; revise/no-go si sigue genérico | render automático por calendario |
| Premiación prevista y luego gesto inesperado | distinguir capa estacional de detonante reactivo | reclasificar toda la campaña como trend |
| Meme conocido sin conversación actual | clasificar lenguaje evergreen si pertinente | inventar que está creciendo |
| Captura única con muchas views | estado puntual, evolución no verificada | afirmar pico/aceleración |
| Tendencia cambia durante render | revalidar y corregir/retirar distribución | publicar por costo hundido |
| Usuario fija frase y concepto | mejorar tratamiento y preservar contrato | rehacer estrategia sin autorización |
| Marca necesita vínculo, no ventas | permitir firma y emoción con objetivo declarado | forzar CTA o producto protagonista |
| Color corporativo sin estudio de reconocimiento | recurso del sistema; atribución suficiente por otro activo | afirmar que sustituye logo probado |
| Libreta realista pero irrelevante | revisar papel/pertinencia, no sólo escala | agrandar logo como arreglo estratégico |
| Wordmark con bajorrelieve pero letras alteradas | falla identidad; corregir ruta | aceptar realismo como fidelidad |
| Meme pierde código al pulirse | recuperar lenguaje reconocible | maximizar acabado por costumbre |
| Imagen estática solicitada | entregar estático revisado | imponer video porque es tendencia |
| Carrusel repite misma tesis | corregir progresión y función de páginas | contar slides como narrativa |
| Todos los checks del PNG pasan; idea genérica | QA creativo/estratégico revise | cinco niveles pass por una prueba técnica |
| Muchos comentarios de crítica | describir contexto/sentimiento con muestra y límites | éxito automático por engagement |
| Sin acceso a analytics | desempeño no medido | atribuir recordación/ventas por criterio interno |
| Producción aprobada sin permiso de publicar | completar resultado reviewable, separar siguiente acción | bloquear todos los renders o publicar automáticamente |
| Falta dato opcional de una prueba | supuesto explícito y continuar | interrogatorio que impide avanzar |

## Regresiones observadas: Viva México y previa 18 (2026-09-16)

Bitácora: `docs/operations/social/2026-09-16-viva-mexico-y-previa-18-production-method.md`.

| Caso / entrada | Conducta esperada | Señal de fallo |
|---|---|---|
| Concepto con moraleja genérica («constancia», «entre muchos») y logo al pie | Aplicar la prueba de cambiar el logo con marcas concretas; si otra categoría la firma igual, cambiar de mecanismo hacia un oficio visible de la casa | Defender la conexión en el caption o en la explicación del autor |
| Operador dice «no logras conectar» | Revisión adversarial (subagente o propia) contra marca/playbook, verificar sus hallazgos antes de adoptarlos y proponer rutas nuevas | Añadir texto explicativo o agrandar el logo |
| Ruta descartada reaparece en el caption | Revisar caption contra rutas descartadas | Pitch colado por la copia final |
| Carrusel cuyo remate niega tocar algo | Mantener la frase final idéntica (tipo, tamaño, posición) a las láminas previas; el impacto sale de la escena | «Mejorar» tipográficamente la frase que la pieza dice no tocar |
| Personas reales del equipo en la pieza | Producir con fotos oficiales, validar caras a tamaño móvil y exigir consentimiento antes de programar | Avatares ilegibles o publicación sin OK de las personas |
| Operador pide «alto impacto» y la pieza es vectorial plana | Diagnosticar luz, contraste, escala, acción y profundidad; subir a escena con cámara/luz/material | Agrandar el mismo número o añadir adornos |
| Edición con máscara para recolorear un elemento | Comparar geometría antes/después; si cambia forma, cantidad o posición, descartar y recolorear determinísticamente | Aceptar un inpainting que «se ve bien» pero cambió el objeto |
| Contraste sobre fuegos, reflejos o luz variable | Scrim gradual local y medición sobre el fondo ya oscurecido, con umbral que haga fallar el render | Medir sobre el plate original o usar un velo rectangular |

## Regresiones observadas: carrusel «Nivel de búsqueda» — GTA VI (2026-09-19)

Corrida: `ai-generations/2026-09-19_nivel-de-busqueda/` (`LEEME.md`, `brief/gta6-visual-study.md`).

| Caso / entrada | Conducta esperada | Señal de fallo |
|---|---|---|
| Trendjacking de una franquicia con varias eras (Vice City 2002 vs GTA VI 2026) | Estudio visual con fuentes y etiquetas `[V]/[O]/[NV]` antes del primer prompt; bloque de estilo que diga también qué NO es | Dirigir la estética de memoria o por la era equivocada (la v1 synthwave ochentera fue rechazada: «no está mal, pero no está bien») |
| Lámina con titular + apoyo casi del mismo peso y color | Escala de voces con una dominante indiscutible (contrato en `efeonce-advertising-creative`); revisar en miniatura | Jerarquía plana: entrada 740 vs dominante 780 en el mismo blanco; agrandar todo por igual |
| Palabra clave en naranja sobre horizonte o skyline encendido | Acento sólo sobre cielo oscurecido; si no se lee, énfasis por peso blanco; registrar la revisión visual cuando p98 marque bajo por luces puntuales | Naranja a 1,0–2,0:1 aceptado porque «es el color de marca», o etiqueta naranja sobre violeta |
| Plate sin cielo para el titular o logo cortado en el borde | Regenerar declarando el layout en el prompt (porcentajes de alto, banda superior de cielo oscuro, base mate reservada) | Tapar con un velo rectangular o subir el scrim hasta apagar la escena |
| Hoja de revisión armada por orden alfabético con una pieza suelta | Hoja en orden de publicación (`c01…c09`); pieza suelta aparte o rotulada fuera de la secuencia | El operador cree que la contraportada no es la última lámina |
| Etiqueta de colaborador larga con dos colaboradores en esquina | Etiqueta corta («Efeonce»); con texto alineado a la izquierda usar `top-end`/`bottom-end`; si `withinCanvas:false`, leer `cursorEvidence[].labelBounds` | «Equipo Efeonce» sale del lienzo o choca con el HUD y se entrega igual |
| Activo de marca (Nexa, logo 3D, nave, mascotas) dentro del mundo del trend | Referencia canónica en la pasada + QA letra por letra y color al 100 % | Color derivado (Nexa azul rey en vez de navy) o letras/órbita alteradas aceptadas por el estilo pintado |
| Código de la IP muy tentador (logo «VI», Pricedown, «Wasted», personajes) | UI y tipografía propias; nombres sólo como referencia nominativa; pauta pasa por revisión legal | Recrear logo, fuente o frases literales del juego «porque es orgánico» |
| Meme con fecha de caducidad conocida | `expires_at` = fecha del lanzamiento; no programar después | Publicar «antes de GTA 6» cuando el juego ya salió |

## Protocolo de evaluación documental

1. Elegir escenarios que ejerciten decisiones diferentes: estacional, reactivo con evidencia incompleta,
   concepto fijado, físico/material, formato secuencial y métricas sin datos.
2. Aplicar la skill al brief hipotético; registrar respuesta esperada, ambigüedad encontrada y ajuste.
3. Comprobar coherencia entre módulo, playbook y templates: mismos estados, no aprobar publicación desde go,
   no convertir investigación deseable en cuota obligatoria, no confundir revisión interna con audiencia.
4. Clasificar resultado como walkthrough documental. Sólo afirmar prueba visual si se produjo y abrió el
   artefacto, y prueba de audiencia si participaron personas con método registrado.
5. Conservar defectos no resueltos como tales. El usuario rechazando una ejecución invalida su aceptación
   visual aunque siga pasando sus checks técnicos. No reescribir el histórico para ocultar el fallo.
